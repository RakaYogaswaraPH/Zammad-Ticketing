RINGKASAN EKSEKUTIF
------------------------------------------------------------

Fitur ini BISA diwujudkan tanpa menambahkan tabel baru.
Database Zammad sudah menyimpan kolom waktu yang diperlukan:

  Kolom yang sudah ada di tabel `tickets`:
  +-- created_at            = Waktu tiket dibuat (masuk)
  +-- close_at              = Waktu tiket ditutup
  +-- last_close_at         = Waktu penutupan terakhir
  +-- first_response_at     = Waktu respon pertama dari agent
  +-- close_in_min          = Durasi penyelesaian (menit) [belum diisi otomatis]
  +-- first_response_in_min = Durasi respon pertama (menit)
  +-- update_in_min         = Durasi respon balasan terakhir (menit)

Strategi: Isi kolom close_in_min & first_response_in_min otomatis
ketika tiket ditutup, lalu buat halaman laporan SLA baru di
menu Reporting yang menampilkan grafik dan ringkasan statistik.


------------------------------------------------------------
BAGIAN 1 -- APA ITU FITUR SLA TRACKER INI?
------------------------------------------------------------

Service Level Agreement (SLA) Tracker adalah:
- Pencatatan otomatis durasi waktu pengerjaan tiket,
  mulai dari tiket dibuat sampai tiket ditutup.
- Track record per tiket: berapa menit/jam/hari tiket diselesaikan.
- Laporan visual berupa grafik pada menu Reporting,
  terpisah dari laporan Elasticsearch bawaan Zammad.
- Tidak bergantung pada Elasticsearch (bisa pakai SQL/PostgreSQL langsung).

Data yang dicatat per tiket:
  -------------------------------------------------
  Metrik                          | Sumber
  --------------------------------+-----------------
  Durasi penyelesaian (menit)     | close_at - created_at
  Waktu respon pertama (menit)    | first_response_at - created_at
  Waktu tiket masuk               | created_at
  Waktu tiket ditutup             | close_at
  Prioritas tiket                 | priority.name
  Grup/Departemen                 | group.name
  Agent penanggung jawab          | owner.fullname
  -------------------------------------------------

BAGIAN 2 -- KOMPONEN YANG PERLU DIBUAT
------------------------------------------------------------

2.1 BACKEND -- Rails (Ruby)
------------------------------------------------------------

[A] Callback Otomatis (TANPA migration)
    File baru: app/models/ticket/tracks_duration.rb
    - Dipanggil setelah tiket berubah state menjadi "closed"
    - Menghitung dan menyimpan:
        close_in_min = (close_at - created_at) / 60
        first_response_in_min = (first_response_at - created_at) / 60
    - Hanya berjalan bila state_type = "closed" dan close_at tidak nil
    - Di-include di app/models/ticket.rb (satu baris)

[B] Controller Laporan SLA
    File baru: app/controllers/sla_reports_controller.rb
    Endpoint yang tersedia:
      GET /api/v1/sla_reports/summary
        => Kartu statistik: total, rata-rata, min, max durasi
      GET /api/v1/sla_reports/chart_data
        => Data titik grafik per hari/minggu/bulan
      GET /api/v1/sla_reports/tickets
        => Daftar tiket dengan durasi (untuk tabel detail)

    Query: langsung ke PostgreSQL menggunakan ActiveRecord.
    Filter yang didukung:
      date_from, date_to  -- rentang tanggal
      group_id            -- filter per grup
      priority_id         -- filter per prioritas
      interval            -- day / week / month

[C] Policy (Otorisasi)
    File baru: app/policies/controllers/sla_reports_controller_policy.rb
    - Hanya agent dan admin yang bisa akses
    - Customer diblokir dari semua endpoint laporan SLA

[D] Route
    Tambahkan di config/routes.rb (scope /api/v1):
      namespace :api, path: '/api' do
        namespace :v1 do
          resources :sla_reports, only: [] do
            collection do
              get :summary
              get :chart_data
              get :tickets
            end
          end
        end
      end

RISIKO RENDAH:
  [OK] Tidak butuh tabel baru -- kolom sudah ada
  [OK] Tidak bergantung pada Elasticsearch
  [OK] Tidak memodifikasi core/framework Zammad
  [OK] Query ke PostgreSQL lebih cepat dan bisa dipahami
  [OK] Tidak ada resiko break pada fitur yang sudah berjalan

CATATAN PENTING:
  [!] Tiket lama yang sudah closed mungkin close_in_min-nya kosong.
      Solusi: jalankan script backfill satu kali:
      UPDATE tickets
      SET close_in_min = EXTRACT(EPOCH FROM (close_at - created_at)) / 60
      WHERE close_at IS NOT NULL AND close_in_min IS NULL;

  [!] Tiket yang dibuka ulang (re-opened): durasi dihitung dari
      created_at sampai last_close_at (penutupan terakhir).

  [!] Chart.js via CDN membutuhkan koneksi internet saat load.
      Alternatif: simpan Chart.js ke app/assets/javascripts/.

  [!] Endpoint SLA Report: hanya untuk user permission 'report'
      (admin/agent). Customer secara otomatis diblokir oleh policy.
